The Quip Network
Trading Competition

Internal summary of the two-day booth demo. Attendees create a trading agent at a kiosk; Quip Network routes the resulting portfolio-optimization job across quantum and classical providers. A leaderboard tracks P&L over the conference and surfaces which provider solved each job.

01 · Overview

What we're building

Attendees walk up to a kiosk, name an agent, set five strategy sliders, and submit. That submission is the competition entry. We're building a similar activation to Base + Coinbase at Consensys Miami — see the reference screens below for context.

The five sliders parameterize a portfolio optimization problem. The server dispatches the job to Quip Network, which routes it to available providers — D-Wave (quantum) and one or more classical solvers. The first provider to return a valid optimum wins the job, and that solution becomes the agent's portfolio until the next retune.

Each attendee receives a QR-coded profile URL for use on their phone for the duration of the conference. The phone profile shows live P&L and lets the user adjust sliders; every adjustment triggers a new optimization through Quip Network.

Rationale

  • The demo runs the production routing layer live, with quantum hardware solving customer-shaped problems in view of attendees and passers-by.
  • Each solved job shows which provider responded fastest. Results display the winning provider; D-Wave wins ~80% of jobs in expectation. The provider badge is the same surface shown to production customers.
  • Surfaces: kiosk, phone profile, booth-TV leaderboard.
  • Each retune triggers a new routing job, so active players generate more live data. Replaces Base's LLM-generated strategy step with a real routing call, so every interaction exercises the product directly.
  • Format follows Base + Coinbase at Consensys Miami, which used a similar setup and saw sustained booth traffic.

05 · Big-screen behavior

Booth TV rotation

The booth TV has four states. State A (top-10 leaderboard) is the default view and reappears between every other state. State B spotlights and state C intros rotate on a timer. State D (new-agent welcome) interrupts the rotation whenever a kiosk submits a new agent.

Strategy adjustments do not trigger a big-screen change. The screen reacts only to new signups, not to ongoing retunes.

Rotation loop

State A (leaderboard) is the anchor; the screen returns to it between every other state.

A (leaderboard) → B (spotlight rank #1) → C (intro) →
A (leaderboard) → B (spotlight rank #2) → C (intro) →
A (leaderboard) → B (spotlight rank #3) → C (intro) →
… cycles through all 10 ranks, then loops back to rank #1.

State D (new-agent welcome) interrupts the loop for ~10s on each new kiosk submission, then the rotation resumes from where it paused.

06 · MVP scope & stretch

MVP scope and stretch items

MVP — required for QTW

Minimum required for the demo

  • Kiosk sign-up: name, X handle, 5 sliders, optional notes, supported-asset preview
  • Quip Network routing job on launch + on every slider re-tune
  • Provider-provenance badge wherever a strategy is shown (kiosk return, phone, big-screen)
  • Personal phone profile via QR-coded secret URL — live P&L + retune
  • Live leaderboard ranked by P&L
  • Big-screen rotator: welcome splash (10s on new signup) + leaderboard + top-10 spotlight rotation
  • Pixel-pattern glyph keyed off player name + slider state (using patternGen.ts)
  • Price oracle integration with a TBD ping cadence and mark-to-market P&L
  • Anti-tamper basics: secret URLs, server-authoritative state, no client-side P&L math
  • Disclosure copy ("paper trading, virtual bankroll, no real funds")
Stretch — only if MVP is fully solid

Optional additions if capacity allows

  • Hashtag-monitored Twitter/X feed sidebar on the big screen (human posts, not LLM)
  • Aggregate "Quip today" stats panel: jobs routed, percent solved by quantum, median latency, total adjustments
  • Per-agent strategy-history view (timeline of retunes and their providers)
  • Public spectator URL (read-only mirror of the big screen) for remote viewers / livestream
  • Recap email to each player at conference close: ranking, retune history, providers used
  • Multi-chain asset basket (exercises routing across heterogeneous data sources)

Explicitly out of scope for v1

LLM trash-talk trollbox · LLM-generated agent personas / backstories · cartoon avatars (we use generative glyphs instead) · in-app trading UI beyond the 5 sliders · real-money custody · cross-conference persistence (tournament resets each event).

07 · Slider → optimization mapping

How the five sliders map to optimization parameters

Slider labels follow Base's wording (kept for accessibility to non-quant visitors). Each slider maps to a real parameter in the optimization problem dispatched to Quip.

Slider Plain meaning Maps to Effect on the QUBO
Trading Activity How willing am I to flip positions? turnover_penalty λ_t Higher activity → lower penalty on deviations from a uniform baseline (more reshuffling allowed).
Risk Preference How much volatility do I accept for return? risk aversion γ The classic mean-variance trade-off coefficient on the covariance term w'Σw.
Trade Size How concentrated can a single position get? max_weight w_max Per-asset upper bound. Higher → bolder bets allowed.
Holding Style Diamond hands vs. quick exits. momentum window τ Shifts the lookback used to compute expected returns. Patient = longer τ; restless = shorter.
Diversification Spread bets vs. concentrate. cardinality K Min number of non-zero positions. This is the integrality constraint that makes the problem natively QUBO-shaped.

Final coefficients and parameter ranges are owned by the optimization-model owner; tracked as a TBD below. The mapping above is a starting point.

HIGH-LEVEL · sliders set the style

Each slider crosses a threshold that flips a high-level visual property. Crossing a threshold causes the glyph to re-pick its palette and pattern math, not just adjust texture.

  • Risk Preferencepalette family — cool (cyan / aurora / electric / forest), neutral (mixed / purple / sunset), or warm (coral / flare / ember / yellow)
  • Trade Sizegeneration mode — noise (organic dots), waves (geometric interference), or mandala (radial)
  • Holding Styleradial symmetry — off (mirror) below 50, on above 50
  • Diversificationray count when radial — 3 / 5 / 7 / 9

LOW-LEVEL · within the chosen style

Within the style selected above, each slider also fine-tunes the texture. Same style + different slider values produces glyphs in the same family with different texture.

  • Trading Activityfrequency / scale of the pattern
  • Risk Preferencealso density / contrast threshold
  • Trade Sizealso cell shape (square / circle / diamond)
  • Holding Stylealso color drift across the canvas
  • Nameseeds the noise + picks a specific palette inside the slider's family

Public views (leaderboard, spotlight) use the name-only derivation so a player's strategy isn't decodable from their public glyph.
